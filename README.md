# Cringearium

**Cringearium** — веб-приложение для онлайн-обучения с адаптивными тестами и ИИ-помощником. Пользователь выбирает курс, изучает материал, решает задания и получает обратную связь по своим ответам.

Проект разрабатывается в рамках магистерской диссертации, посвящённой адаптивному обучению с использованием искусственного интеллекта. Backend написан на Go, frontend — на React и TypeScript.

## Возможности

- **Учебные курсы.** Модули с теорией, иллюстрациями, разобранными примерами и заданиями для самопроверки.
- **Обычные тесты.** Подготовленные вопросы с вариантами ответов, проверкой результата и сохранением попыток.
- **Адаптивная ИИ-практика.** Задания подбираются с учётом темы, предыдущих ответов и состояния навыков пользователя.
- **Кринжик.** ИИ-помощник для обсуждения учебных вопросов. Переписки сохраняются, ответы поступают по мере генерации.
- **Личный кабинет.** Регистрация, вход, список доступных курсов и сохранение учебного прогресса.
- **Завершение курса.** Итоговая проверка и персональная страница окончания обучения.
- **Панель администратора.** Просмотр пользователей, курсов и состояния сервисов приложения.
- **Мобильный интерфейс.** Раскрывающаяся навигация и выдвижное оглавление курса.

В каталоге представлены математика, Python, русский язык, психология, философия и мемология. Для каждого направления есть два варианта: с обычной практикой и с адаптивной практикой на базе ИИ. Теоретические материалы внутри пары одинаковы.

## Как работает адаптивная практика

Курс разбит на отдельные навыки, связанные с учебными материалами. Для навыков могут быть заданы предварительные знания: например, перед решением квадратного уравнения может потребоваться повторить преобразования линейных уравнений.

1. Приложение собирает контекст текущей темы, результаты обычных тестов и предыдущих ИИ-заданий пользователя.
2. Backend определяет план раунда: какие навыки проверить, к каким материалам обратиться и какую сложность выбрать.
3. Языковая модель формулирует задания по этому плану. Полученные данные проверяются перед показом пользователю.
4. После ответов обновляется профиль навыков и подбирается следующий раунд. Если нужны предварительные знания, повторение выделяется в отдельный раунд.
5. В конце пользователь видит результаты и рекомендации по дальнейшей работе.

Профиль навыков сохраняется между сессиями. Отсутствие ответов считается недостатком данных, а не признаком слабых знаний. Решения о выборе навыков принимает backend; языковая модель отвечает за формулировку заданий и обратной связи.

## Архитектура

Приложение разделено на сервисы. Frontend обращается к единому API через **gateway**, который маршрутизирует запросы и проверяет доступ к защищённым ресурсам. Основные сервисы имеют собственные базы данных в PostgreSQL и обмениваются данными через HTTP API.

| Сервис | Ответственность |
| --- | --- |
| `gateway` | Единая точка входа, маршрутизация и проверка доступа |
| `auth` | Пользователи, регистрация, аутентификация и выпуск токенов |
| `courses` | Каталог, учебные материалы, обычные тесты, навыки и прогресс |
| `ai-tests` | Адаптивные сессии, планирование раундов, профиль навыков и взаимодействие с LLM |
| `ai-chat` | Переписки с Кринжиком, генерация ответов и ограничения запросов |
| `payment` | Заготовка платёжного сервиса; полноценная оплата пока не реализована |

### Ports and adapters

Предметные сервисы `auth`, `courses`, `ai-chat` и `ai-tests` построены по архитектуре **ports and adapters** — гексагональной архитектуре. Бизнес-логика отделена от HTTP, базы данных и конкретного поставщика языковой модели.

```text
services/<service>/
├── cmd/api/             # Запуск и связывание зависимостей
└── internal/
    ├── domain/          # Предметные модели и правила
    ├── application/     # Сценарии приложения
    ├── ports/           # Интерфейсы сценариев и внешних зависимостей
    └── adapters/        # HTTP, PostgreSQL, LLM и межсервисные клиенты
```

- **Входные адаптеры** принимают HTTP-запросы, проверяют формат данных и вызывают сценарии через входные порты.
- **Application и domain** определяют поведение приложения: проверку ответов, завершение учебных страниц, выбор навыков и подготовку плана практики.
- **Выходные порты** описывают необходимые ядру операции с хранилищем, другими сервисами и языковой моделью.
- **Выходные адаптеры** реализуют эти интерфейсы. PostgreSQL-адаптеры выполняют SQL-запросы и транзакции, LLM-адаптеры работают с API модели.
- **Точки входа** в `cmd/api` создают реализации и передают их сценариям приложения.

Например, при сдаче обычного теста application-слой вычисляет результат и решает, нужно ли завершить страницу. Адаптер PostgreSQL сохраняет попытку, ответы и изменения прогресса в одной транзакции. Бизнес-сценарий при этом не содержит SQL.

Gateway выполняет инфраструктурную роль маршрутизатора, а `payment` пока остаётся заготовкой и не имеет полного набора предметных слоёв.

## Структура репозитория

```text
.
├── frontend/            # React-приложение и статические изображения
├── services/            # Backend-сервисы
├── content/courses/     # Авторские материалы и каталог навыков
├── scripts/             # Подготовка и проверка учебного контента
├── internal/            # Общий код и вспомогательные средства тестирования
├── deploy/postgres/     # Инициализация баз данных
├── .github/             # CI и сценарии проверки приложения
└── compose.yaml         # Конфигурация запуска всех компонентов
```

Учебные материалы поставляются через версионированные миграции сервиса `courses`. Изменения уже опубликованного контента оформляются новой миграцией, чтобы обновлять существующие установки и сохранять историю обучения.

## Запуск

Для запуска приложения нужны **Docker** и **Docker Compose**. Для работы ИИ-функций также требуется доступ к совместимому LLM API.

Перед запуском настройте параметры PostgreSQL, подписи JWT и подключения к языковой модели через переменные окружения, используемые в [compose.yaml](compose.yaml).

Из корня репозитория:

```bash
docker compose up --build -d
```

После запуска:

- Приложение: [http://localhost:3000](http://localhost:3000).
- API gateway: [http://localhost:8080](http://localhost:8080).
- Проверка доступности gateway: [http://localhost:8080/health](http://localhost:8080/health).

Базы данных и остальные backend-сервисы доступны внутри Docker-сети. Миграции применяются при запуске сервисов, данные PostgreSQL сохраняются в отдельном volume.

Просмотр логов:

```bash
docker compose logs -f
```

Остановка приложения:

```bash
docker compose down
```
