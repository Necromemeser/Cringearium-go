# Приложение в одном контейнере

Корневой `Dockerfile` собирает React и пять Go-сервисов: auth, courses,
ai-chat, ai-tests и gateway. В готовом образе Nginx раздаёт frontend и
проксирует API, Supervisor запускает и перезапускает процессы. PostgreSQL
работает отдельным контейнером. Заготовка payment в этот образ не входит.
Бизнес-логика и разделение backend на ports and adapters сохраняются.

Помимо Dockerfile нужны конфигурация Nginx и два небольших сценария в
`deploy/bundled/`: подготовка баз/запуск процессов и проверка готовности.
Исходный `compose.yaml` продолжает запускать сервисы раздельно.

## Локальный запуск

Нужны Docker и Docker Compose. Укажите в окружении или локальном `.env`
следующие параметры, не добавляя секреты в Git:

| Переменная | Назначение |
| --- | --- |
| POSTGRES_USER | Пользователь PostgreSQL; по умолчанию cringearium |
| POSTGRES_PASSWORD | Обязательный пароль PostgreSQL |
| JWT_SECRET | Обязательный постоянный секрет подписи токенов |
| ADMIN_PASSWORD | Обязательный пароль admin@mail.ru, 8–72 байта |
| LLM_BASE_URL | Адрес совместимого OpenAI API без `/chat/completions` |
| LLM_API_KEY | Ключ API |
| LLM_MODEL | Название модели |
| APP_PORT | Порт приложения на хосте; по умолчанию 3000 |

```bash
docker compose -f compose.bundled.yaml up --build -d
```

Откройте http://localhost:3000. Проверка готовности:
http://localhost:3000/healthz. Первый запуск включает миграции, создание
администратора и 50 учебных пользователей, поэтому занимает дополнительное время.

```bash
docker compose -f compose.bundled.yaml logs -f app
docker compose -f compose.bundled.yaml down
```

Остановка без `-v` сохраняет данные. Удаление volume удалит базу данных.
Новый режим использует собственный `bundled_postgres_data`: данные прежнего
запуска автоматически не переносятся. Перед переносом существующей установки
сделайте резервные копии и восстановите четыре базы в новом PostgreSQL.

## Развёртывание на контейнерной платформе

Создайте два сервиса в одной закрытой сети:

1. PostgreSQL 17 с постоянным диском в `/var/lib/postgresql/data`.
   Передайте ему POSTGRES_USER и POSTGRES_PASSWORD. Не публикуйте порт 5432
   в Интернет.
2. Образ приложения, собранный из корня репозитория по `Dockerfile`.
   Публичный HTTP-порт контейнера — **80**. HTTPS и домен настройте
   на стороне платформы. Внешний прокси должен поддерживать SSE,
   отключать буферизацию ответов `/api/` и разрешать длительные соединения.

В приложении укажите обязательные переменные из таблицы и
`POSTGRES_HOST` — внутреннее имя/адрес сервиса PostgreSQL на вашей платформе.
При запуске через предоставленный Compose это имя задаётся автоматически.
Дополнительные параметры образа:

| Переменная | Значение по умолчанию |
| --- | --- |
| POSTGRES_PORT | 5432 |
| POSTGRES_SSLMODE | disable; для TLS задайте режим, соответствующий серверу |
| POSTGRES_DB | postgres; служебная база для первоначального подключения |
| POSTGRES_WAIT_TIMEOUT | 120 секунд, допустимо 1–600 |
| AUTH_DATABASE | cringearium_auth |
| COURSES_DATABASE | cringearium_courses |
| AI_CHAT_DATABASE | cringearium_ai_chat |
| AI_TESTS_DATABASE | cringearium_ai_tests |
| JWT_TTL | 24h |

Приложение ожидает PostgreSQL и создаёт отсутствующие базы. Пользователю БД
нужно право CREATEDB либо четыре заранее созданные базы, принадлежащие ему.
Миграции выполняют сами сервисы. Изменение POSTGRES_PASSWORD в настройках
уже инициализированного PostgreSQL не меняет пароль роли: его нужно отдельно
изменить в самой БД и затем обновить конфигурацию приложения.

Путь readiness/healthcheck — `/healthz`. Он проверяет Nginx, gateway,
четыре предметных сервиса и подключение к PostgreSQL, не обращаясь к LLM.
Для начального запуска предусмотрите не менее 180 секунд отсрочки проверки;
для корректной остановки — 60 секунд. Встроенный Docker HEALTHCHECK также
использует этот адрес. Сам Docker не перезапускает контейнер только из-за
статуса unhealthy; падения дочерних процессов обрабатывает Supervisor.

Начальный ориентир ресурсов: 1 ГиБ RAM приложению и 512 МиБ–1 ГиБ PostgreSQL.
Окончательные лимиты выбирайте после проверки одновременных тестовых сессий.
Все журналы доступны в логах контейнера; секреты передавайте через настройки
окружения платформы. Постоянный диск приложению не требуется.

Обновление приложения требует пересборки одного образа и перезапуска
контейнера. JWT_SECRET сохраняйте между обновлениями, иначе токены входа
перестанут работать. ADMIN_PASSWORD при запуске синхронизирует пароль
администратора с указанным значением.

## Проверки

GitHub Actions собирает оба варианта развёртывания. Для объединённого образа
проверяются API, интерфейс и картинки, доступ администратора и учебных
пользователей, SSE без буферизации, восстановление процесса и сохранение
переписки/токена после перезапуска. Smoke-сценарии предназначены только для
одноразовой тестовой установки: они создают и изменяют данные.
