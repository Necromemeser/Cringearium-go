# Cringearium

Cringearium — образовательная платформа с курсами, тестированием и инструментами на базе ИИ. Этот репозиторий содержит новую версию backend на Go и frontend на React.

> Проект находится в разработке. Состав реализованных функций и конфигурация сервисов могут меняться.

## Возможности

- Учебные курсы, разделённые на модули и страницы с теорией и тестами.
- Обычные тесты с заранее подготовленными вопросами и вариантами ответов.
- Адаптивные тесты: ИИ формирует следующую практику с учётом предыдущих ответов.
- ИИ-чат.
- Регистрация и аутентификация с использованием JWT.
- Отдельный сервис платежей; интеграцию оплаты следует считать незавершённой, пока она не проверена в целевом окружении.

## Технологии

- **Backend:** Go, HTTP API.
- **Frontend:** React, TypeScript, Vite.
- **Хранение данных:** PostgreSQL.
- **Инфраструктура:** Docker, Docker Compose.
- **ИИ:** API-совместимый LLM endpoint; параметры по умолчанию в примере окружения настроены на DeepSeek.
- **CI:** GitHub Actions — сборка frontend и проверки/сборка Go-сервисов.

## Архитектура

Приложение разделено на сервисы. Gateway предоставляет единую точку входа для frontend и маршрутизирует запросы к backend-сервисам.

| Компонент | Назначение | Внутренний порт |
|---|---|---:|
| `gateway` | Единая HTTP-точка входа | 8080 |
| `auth` | Регистрация, вход и проверка доступа | 8081 |
| `courses` | Курсы, разделы, страницы и обычные тесты | 8082 |
| `payment` | Платёжная функциональность | 8083 |
| `ai-chat` | Чат с ИИ | 8084 |
| `ai-tests` | Адаптивные тесты и обратная связь | 8085 |
| `frontend` | Web-интерфейс | 80 в контейнере |

Frontend публикуется на порту **3000** хоста, gateway — на порту **8080**. Остальные backend-сервисы доступны внутри Docker-сети.

У сервисов отдельные базы данных PostgreSQL: `cringearium_auth`, `cringearium_courses`, `cringearium_payment`, `cringearium_ai_chat` и `cringearium_ai_tests`. Данные PostgreSQL сохраняются в Docker volume.

Основные каталоги:

```text
.
├── compose.yaml
├── deploy/
│   └── postgres/
├── frontend/
└── services/
    ├── auth/
    ├── courses/
    ├── payment/
    ├── ai-chat/
    ├── ai-tests/
    └── gateway/
```

В сервисах backend код организован по слоям: точка входа, application/domain-логика и адаптеры для внешних систем и хранения данных.

В реализованных сервисах (`auth`, `courses`, `ai-chat`, `ai-tests`) используются ports and adapters:

- `domain` содержит модели, `application` — сценарии и бизнес-решения.
- `ports` определяет входные интерфейсы сценариев, выходные интерфейсы зависимостей и ошибки контрактов. Ядро не зависит от SQL, HTTP или конкретного LLM-провайдера.
- `adapters` преобразует HTTP-запросы, ответы внешних API и ошибки хранилища в контракты ядра. `cmd/api` связывает реализации с портами.
- При сдаче теста application определяет оценку, тип assessment и необходимость завершения страницы. PostgreSQL-адаптер атомарно сохраняет попытку, ответы, assessment и прогресс.

В Docker job CI дополнительно выполняется `.github/scripts/smoke_backend.py`: через gateway и PostgreSQL проверяются регистрация, запись на курс, успешная и неуспешная сдача трёх типов тестов, прогресс и повторная сдача. Скрипт создаёт собственные данные и предназначен для одноразового тестового Compose-окружения; вызовы внешнего LLM ему не нужны.


## Контекст адаптивной практики

Поле `topic_page_id` API принимает страницу AI-практики или теории выбранного курса. Для AI-практики backend берёт теорию и обычные тесты её раздела; для страницы теории — сам материал и тесты того же раздела. Без `topic_page_id` используется весь курс. Неизвестные страницы и страницы обычных тестов отклоняются. Это начальная политика определения контекста; отдельная модель учебных навыков пока не введена.

В генерацию передаются результаты обычных тестов с выбранными ответами и конкретные ошибки завершённых адаптивных раундов. Новая сессия учитывает до трёх завершённых попыток того же пользователя по той же практике за последние 30 дней (для режима всего курса — по всему курсу). Отсутствие ответа не интерпретируется как ошибка. Материалы и исходные свидетельства сохраняются в `context_snapshot` и используются во втором раунде и итоговой обратной связи. Старые сессии с пустым снимком продолжают получать контекст через `courses`.

Для двух математических вариантов курса добавлен пилот из девяти навыков и зависимостей между ними. Разметка хранится в `learning_skills`, `learning_skill_prerequisites`, `page_learning_skills`; коды одинаковы между вариантами курса, а страницы относятся к конкретному курсу. При необходимости контекст включает явно связанные предварительные материалы. Остальные курсы продолжают работать без разметки.

В `ai-tests` профиль хранится отдельно от курса: `learner_skill_states` содержит состояние пользователя по навыку, `learning_evidence` — свидетельства по ответам. Один вопрос проверяет один основной навык. Backend определяет для каждого места в раунде навык, материал, условную сложность и причину выбора; план сохраняется в `adaptive_rounds.learning_plan`. LLM формулирует вопрос по этому плану, а backend отклоняет несовпадающие метки. Проверка меток не доказывает фактическую сложность или содержательную корректность сгенерированного задания.

Правила `skills-v1`:

- Начальное состояние — «недостаточно данных», а не «слабые знания».
- Две последние ошибки в разных заданиях требуют дополнительной практики.
- Для «предварительно освоено» нужны минимум шесть разных заданий, свидетельства минимум из двух сессий, три последних правильных ответа и не менее 80% успехов среди последних пяти. Это эвристика пилота, не калиброванная вероятность знаний.
- После 14 дней без нового независимого свидетельства предварительно освоенный навык получает отметку «пора повторить». Отдельного календаря повторений пока нет.
- Повтор задания с тем же нормализованным текстом и вариантами не меняет оценку и не откладывает повторение. Перефразирование пока не распознаётся как семантический дубликат.
- При известном пробеле в предварительном навыке ему отдаётся приоритет. Неизвестный предварительный навык сам по себе не блокирует обучение.

Ответы, завершение раунда и обновление профиля фиксируются одной транзакцией. Повторные и параллельные отправки не применяют свидетельства дважды. Ошибка последующей генерации не отменяет уже сохранённые знания. API `GET /api/adaptive-tests/profile?course_id=...&topic_page_id=...` проверяет доступ к курсу и возвращает только профиль текущего пользователя; интерфейс показывает состояния и следующий фокус.

Профиль пока обновляется только по новым адаптивным вопросам с проверенной привязкой к навыку. Старые вопросы не размечаются задним числом. Обычные тесты передаются в контекст LLM, но не повышают счётчики навыков до отдельной авторской разметки. Сохраняются два раунда и прежние названия стратегий; точный выбор заданий математического пилота задаётся сохранённым планом. Проверенный банк заданий, более подробный разбор ошибок и оценка отложенного учебного эффекта — следующие этапы.

Интеграционные Go-тесты используют `TEST_DATABASE_URL` (PostgreSQL URL). Каждый тест создаёт и удаляет только свою временную схему; пользователю БД требуется право создавать схемы. Без этой переменной интеграционные тесты пропускаются. В Go job GitHub Actions PostgreSQL и переменная настроены, поэтому эти проверки выполняются обязательно. Проверяются корректность учебного контекста через HTTP, сохранение ошибок и снимка, использование истории, ограничения по давности и количеству, изоляция пользователей, курсов и практик. Внешний LLM заменён тестовым генератором.

## Запуск локально через Docker Compose

Потребуются Docker Engine или Docker Desktop и Docker Compose.

1. Склонируйте репозиторий и перейдите в каталог проекта:

   ```bash
   git clone https://github.com/Necromemeser/Cringearium-go.git
   cd Cringearium-go
   ```

2. Создайте локальный файл окружения на основе шаблона:

   **Linux/macOS**
   ```bash
   cp .env.example .env
   ```

   **PowerShell**
   ```powershell
   Copy-Item .env.example .env
   ```

3. Заполните значения в `.env`. Минимально задайте имя и пароль PostgreSQL, длинный случайный `JWT_SECRET` и ключ API выбранного LLM-провайдера. Пример содержит адрес API и название модели по умолчанию; убедитесь, что выбранная модель доступна вашему ключу.

   ```dotenv
   POSTGRES_USER=cringearium
   POSTGRES_PASSWORD=replace-with-a-strong-password

   JWT_SECRET=replace-with-a-long-random-secret
   JWT_TTL=24h

   LLM_BASE_URL=https://api.deepseek.com
   LLM_API_KEY=your-api-key
   LLM_MODEL=deepseek-v4-flash
   ```

   Не добавляйте настоящий `.env` или секреты в Git.

4. Соберите образы и запустите приложение:

   ```bash
   docker compose up --build
   ```

5. Откройте frontend: [http://localhost:3000](http://localhost:3000). Gateway доступен по адресу [http://localhost:8080](http://localhost:8080).

Остановить контейнеры:

```bash
docker compose down
```

Остановить контейнеры и удалить сохранённые данные PostgreSQL:

```bash
docker compose down -v
```

> **Внимание:** команда с `-v` удаляет volume базы данных. Используйте её только если действительно хотите сбросить локальные данные.

## Разработка без Docker

Для Go-backend установите версию Go, указанную в `go.mod` или новее, совместимую с проектом. Для frontend используйте Node.js и npm.

Проверить Go-код и запустить тесты:

```bash
go test ./...
go build ./...
```

Собрать frontend:

```bash
cd frontend
npm ci
npm run build
```

Для локального запуска отдельных компонентов потребуются PostgreSQL, корректные переменные окружения и адреса зависимых сервисов. Для полного локального окружения рекомендуется использовать Compose.

## Учебный контент: парные курсы математики

В проект добавляются две версии одного учебного курса для обучения и дальнейшего сравнения форматов практики:

- **«Математика: курс с ИИ»** — теория и примеры по линейным, квадратным и тригонометрическим уравнениям, обычные тесты и страницы адаптивной практики.
- **«Математика: обычные тесты»** — те же тематические модули и учебные материалы, но практика проходит через фиксированные тесты без адаптивной генерации.

Структура модулей:

1. **Линейные уравнения:** преобразования, раскрытие скобок, проверка решения и особые случаи.
2. **Квадратные уравнения:** неполные уравнения, дискриминант, формула корней и теорема Виета.
3. **Тригонометрические уравнения:** базовые решения, периодичность и отбор решений на заданном промежутке.

Обе версии предназначены для сохранения сопоставимого содержания. Для исследовательского сравнения результаты следует собирать на одинаковых независимых входных и итоговых тестах, а время и объём практики — по возможности удерживать сопоставимыми.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `POSTGRES_USER` | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `JWT_SECRET` | Секрет для подписи JWT |
| `JWT_TTL` | Срок действия токена, например `24h` |
| `LLM_BASE_URL` | Базовый URL API языковой модели |
| `LLM_API_KEY` | Ключ API языковой модели |
| `LLM_MODEL` | Идентификатор используемой модели |
